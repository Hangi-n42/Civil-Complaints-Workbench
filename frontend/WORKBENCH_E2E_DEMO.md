# 민원 워크벤치 시연

한 건의 민원을 선택해 유사 사례의 근거를 확인하고, 답변 초안을 검토·편집하는 흐름입니다. 관제 화면에서는 저장된 분석 결과와 자료 출처를 살펴봅니다.

## 준비

화면의 순서만 확인하려면 아래 동선을 읽으면 됩니다. 직접 시연할 때는 [독립 실행 안내](../docs/30_manuals/local_dev_runbook.md)에 따라 복사 자산과 모델을 준비하고 API와 화면을 실행합니다. 전용 profile의 화면 주소는 `http://127.0.0.1:3092/`입니다. 준비 점검, API 응답, 브라우저 동작은 각각 확인합니다.

[대표 화면](../README.md)은 합성 민원 3건을 케이스 API로 불러온 상태입니다. 이 캡처에서 확인한 동작은 민원 전환, 원문 접기·펼치기, 수기 초안 편집과 새로고침 후 초안·검토 상태 복원입니다.

## 민원 선택에서 초안 편집까지

| 화면에서 할 일 | 확인할 내용 |
| --- | --- |
| 첫 화면 `/`의 민원 목록에서 케이스를 선택합니다. | `/workbench`에 선택한 민원과 요약, 핵심 요청, 확인할 사항이 표시됩니다. |
| **유사민원검색**을 누르고 결과를 펼칩니다. | 현재 민원에 참고할 본문과 저장된 과거 답변을 구분해 읽습니다. |
| **답변 초안 및 비교** 영역에서 **초안**을 누릅니다. | 로컬 모델을 사용하는 경로입니다. 생성된 초안의 주장이 제시된 근거로 뒷받침되는지 확인합니다. 모델이나 검색 자산에 문제가 있으면 화면의 오류 안내를 확인합니다. |
| 편집 칸을 수정하고 같은 브라우저에서 같은 민원을 다시 엽니다. | 수정한 초안과 검색 결과를 다시 확인합니다. **검토중**, **처리완료**는 이 브라우저에서 보관하는 작업 상태입니다. |

과거 사례가 현재 건의 조치를 확인해 주는지, 일정·담당 부서가 실제 근거에 있는지 살펴보면 초안 검토의 기준을 보여줄 수 있습니다.

## 관제에서 자료 출처 읽기

1. `/intelligence`에서 이슈 경보, 행정 인사이트, 중복 민원 탭을 확인합니다.
2. **자료 출처와 실행 구분**에서 최근 실행 기록의 출처 정책, 분석 기준 시각, 생성 방식을 읽습니다. 이전 저장 자료에 관련 기록이 없으면 **미확인**으로 표시됩니다.
3. **저장 결과 다시 조회**로 저장된 내용을 읽습니다. 명시적 분석 API를 실행했을 때의 응답은 **새 분석 실행 결과**로 구분됩니다.
4. 중복 후보에서 근거와 검토 상태를 확인합니다. 확인·분리·반려를 시연하려면 별도 복사한 관제 DB를 사용합니다.

재생 자료의 시각과 지도 위치는 시연 설정에 따라 배치될 수 있습니다. `모의 생성(fake)`은 시연용 생성 방식입니다. 자세한 의미는 [출처와 실행 표시 안내](../docs/30_manuals/complaint_intelligence_demo_replay.md#출처와-실행-표시-읽기-2026-11-05)를 참고하세요.
